Еще один use case, который всплыл в связи с экспортом/импортом. Объекты проекта роль, локация, деталь, время действия имеют поле "описание", которое может содержать важную информацию. Например, Кирилл, 33 года, предприниматель-неудачник, одетый во всё мятое. 
1. При первом появлении объекта в тексте это описание должно быть добавлено в текст. При последующих появлениях объекта в тексте описание добавлять не нужно. Сказанное в этом пункте имеет отношение к экспорту, когда структуру проекта переводим в плоский текст.
2. Теперь как это может быть в интерфейсе. В тексте, связанным с карточкой, в которой есть ссылки на такие объекты, должна быть возможность увидеть описание объекта.
3. Я придумал два способа, может быть ты предложишь что-то получше. Первый способ: сделать по аналогии с тегом abbr в html, объект выделяется в тексте (например, подчеркивание прерывистой линией), при подведении курса появляется описание. Второй способ: объект также должен быть выделен в тексте. Двойной клик на объект открывает список объектов указанного типа в панели приложения и выделяет тот, по имени которого кликнул пользователь.
4. Разумеется всё выше сказанное имеет место в том случае, если описание есть.

  - подсказка при наведении в реальном рабочем окне редактора (в моём дымовом тесте окно было отдельное, без полноэкранного режима TinyMCE);
  - привязка/снятие чипа и удаление объекта — карточка, открытая в редакторе, должна перечитаться уже с изменённой разметкой, а набранный текст при этом не потеряться;
  - сохранение текста — я изменил момент, когда Electron отвечает на save-content, и убрал обнуление файла при «нечего сохранять»; переключение между карточками и
    автосохранение стоит погонять;
  - экспорт в PDF на реальном проекте с картинками — печать идёт из временного каталога, а не из файлов проекта.

  Логи приложения по этим операциям пишутся (refs, сохранение, экспорт) — если что-то пойдёт не так, они помогут.
